## Architecture (decided — do not re-litigate; implement)

1. **Engine facade:** cfg-swap inside `inference.rs` — `#[cfg(desktop)]` on sidecar-only fns; `#[cfg(mobile)]` tail re-exports `start/start_if_no_model/restart/shutdown` from new `src-tauri/src/engine_inproc.rs`. That module owns a dedicated inference thread (the `!Send` `EngineHandle`, mpsc commands), maps `Engine`/`EngineStatus`/`EngineInfo` + `engine-ready/-restarting/-failed` events onto `EngineBackend::load → session → stream`, keeps fail-closed sha256 gating via `prepare_stack`/`VerifyCache` fed from catalog pinned hashes. `tier_select.rs`, `cloud/download.rs`, `lib.rs` compile unchanged. Engine-thread panics → `Failed` (never hung); restart resolves in-flight requests with an Error event; no user text/token material in release logs.
2. **Streaming:** `chat_stream(request_id, messages, opts, Channel<ChatEvent>)` runs the calc tool-loop Rust-side (transcribe `src/calc-loop.js` — its header says so); `ChatEvent = Delta|Done{content, calculations, stats}|Error`; `chat_complete` for the two non-stream sites; `chat_cancel` → AtomicBool → `ControlFlow::Break`. Tool formats per family (Llama-3.2 JSON-function; Qwen3 `<tool_call>`) in `engine_inproc/tools.rs`; add `Role::Tool` to kpack-engine. **Tool registry is a CLOSED SET (calc only)** — unknown tool names become tool-error results, never dispatched. Partial-turn flush: checkpoint accumulated assistant text to convstore during generation (kill-restore gate). JS: new `src/transport.js` seam; desktop wraps existing fetch+`streamWithTools` untouched; mobile uses invoke+Channel; exactly the 3 app.js sites change (~1648/1785/2006). Mobile CSP without `127.0.0.1` via `tauri.android.conf.json`.
3. **Session persistence + prefix-KV reuse (task 1.5 — SCHEDULED, not contingent):** keep `EngineSession` alive per chat, append-only rendering so history isn't re-prefilled each turn. Without it, first-token latency hits 25–40 s mid-conversation on the A22. Measure at Checkpoint 1 to order the work.
4. **Storage:** models already land in `<app_data>/models` (verified) — leave alone. New `resources_embed.rs` (`cfg(mobile)`): `include_bytes!` catalog.json+covers, materialize to `<app_data>/resources` at setup (idempotent, rewrite on version change); `resources_root` gets a mobile branch; all consumers unchanged. Android bundle ships no desktop binaries — set `"bundle": {"resources": null}` in `tauri.android.conf.json`. **It must be `null`, not `{}`.** Tauri merges platform config with `json_patch::merge`, i.e. RFC 7386 JSON Merge Patch (`tauri-utils/src/config/parse.rs`), where an object patch merges *recursively*: `{}` is a silent no-op that leaves the desktop resource map fully intact, and only `null` removes the key. The `{}` form was in this brief originally and shipped 239 MB of Windows `.dll`/`.exe` (llama, OCR/tesseract, pdfium, x86 embedder GGUF) into the APK assets before it was caught — see the CP0 section of `verification-milestone-mobile-p1.md`. Verify the fix against the built artifact (`assets/` should hold only `tauri.conf.json`), never against the config source. The same `{} != null` trap applies to *any* key you intend to clear in a platform config file.
5. **Auth:** six keyring fns in `cloud/store.rs` move behind new `cloud/secure_store.rs` — desktop body verbatim; Android body → Kotlin `SecureStore` (AndroidKeyStore AES-256-GCM, non-exportable, random 96-bit IV per encryption stored with ciphertext, tag verified) via `jni`+`ndk_context`, fallback = Tauri `register_android_plugin`. **Move `keyring` to `[target.'cfg(not(target_os="android"))'.dependencies]`** — keyring v3 silently mocks in-memory on unsupported targets. Smoke-test the JNI bridge BEFORE writing crypto. TLS: ureq→rustls+webpki-roots verified portable; on-device sign-in is still a checkpoint.
6. **Self-update:** new `src-tauri/src/app_update.rs` — reuse `catalog_dist`'s `get_capped`/`parse_and_verify`/curator key (promote to `pub(crate)`); per-file downgrade guard via existing `read/write_highest_version` + second state file; APK via `run_public_download`; **APK `url` must pass `download_host_allowed`**; refusals surfaced in UI + local log; `versionName` rendered as text. Install via Kotlin shim: `canRequestPackageInstalls` → settings intent when needed → FileProvider `ACTION_VIEW`. Never silent. Commands: `check_app_update` (launch + daily JS timer), `download_app_update`, `install_app_update`.
7. **Identity/hardening:** `tauri.android.conf.json` with `identifier: com.cleophis.app` (desktop keeps `.desktop`); REGENERATE `gen/android` first — everything later edits it; diff against the P0 scaffold before deleting anything. Manifest batch: `allowBackup=false` + backup/data-extraction XMLs, `REQUEST_INSTALL_PACKAGES`, FGS `specialUse` service (justification: local AI text generation at explicit user request, no network) started/stopped around `chat_stream`, optional `POST_NOTIFICATIONS`, `FLAG_SECURE` toggle command (default off), `file_paths.xml` updates entry. Release: `abiFilters arm64-v8a` only; `debuggable=false`; minify stays on.
8. **Tiering:** `hardware.rs` Android branch — `SocCaps{dotprod, i8mm, max_core_khz}` via `getauxval(AT_HWCAP/2)` + cpufreq sysfs; `tier_for_mobile`: mid (4B) only if RAM ≥ 8 GB AND (i8mm OR ≥ 2.75 GHz); else low; `<4 GB` → `HardwareInfo.supported=false` → honest "not yet" onboarding screen.
